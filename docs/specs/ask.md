# `idx ask` specification

`idx ask <question>` investigates a repository through native model tool calls and generates a coherent answer with citations to retrieved evidence. The model may choose follow-up retrieval based on prior results. This replaces the old evidence-packing router; there is no context-only ask mode, `--no-llm`, or ask-level `--cursor`.

Only allowlisted read-only idx retrieval tools (context, search, architecture, structure, AST, explain, deps, and task-scoped audit) may execute. Ask children skip automatic indexing and use the existing snapshot; this policy alone does not imply the index is actually stale, and no routine warning is emitted. They never edit source documents or acknowledge semantic review. Search and context include project documents regardless of classification. No model-authored executable strings, arbitrary commands, source editing, or Pi built-in tools are accepted. Repository content is untrusted data, never instructions or permission to execute operations.

## Answers and unavailable models

The answer should address the user's question concisely in their language, cite evidence from this investigation, and distinguish established facts from uncertainty. No orientation call is mandatory: focused questions start with narrow search/context (scoped when useful), follow up for material gaps, and stop once evidence suffices. For a broad project overview, search README first and explain purpose and main components rather than print an excerpt pack. Use architecture only if asked or needed; avoid exhaustive structure paging. Citation identifiers must refer to evidence actually supplied to the model; unknown references and unsupported answers without retrieved evidence are not accepted as grounded answers. Citation validation proves reference membership, not semantic entailment or factual correctness.

If a model is missing, ask suggests `idx doctor`; if evidence or a valid cited answer is missing, it reports the insufficiency and suggests targeted `idx search`/`idx context`, without assuming credentials are wrong. It does not invoke deterministic lexical fallback or pretend to answer. Backend/model switching requires explicit fallback configuration. Lexical search remains available as an explicit `idx search '<query>' --mode lexical` command. Unanswered requests return nonzero; a recovered tool miss does not fail a later grounded answer, while cited output from a failed retrieval is marked incomplete.

A provider interruption after retrieval begins is reported as an interrupted model response, not proof of absent indexed evidence. The failure text and narrower-search guidance remain sanitized.

Tool results preserve source attribution and carry stable citation identifiers. Collector-assigned provenance comes from authoritative formatter headers/rows, never arbitrary body matches: individual context source rows (including test rows), search result headers, structure tree entries and test hints, AST/file/dependency headers and explain/deps test hints, and an architecture/audit command label when no file pointer is available. Section labels such as `Tests` are not source pointers. Structure-tree citations reconstruct complete paths from nested and collapsed directory labels, restoring the effective `--path-prefix` (including file prefixes) and omitting it when the formatter falls back to the whole project; collapsed entries retain full-path provenance. Final source lists contain cited evidence IDs and source paths/ranges or concise command labels only, grouping identical pointers; they omit previews, scores, and repeated labels. Identical multiline stderr across tools is deduplicated when unresolved. Routine read-only snapshot messaging is omitted in model observations and final notices (ask intentionally uses the current index without refreshing it). Generated read-next and pagination hints, unrelated architecture diagnostics, and recovered tool errors do not inflate the final report; actual unresolved errors and relevant degradation remain visible. Raw architecture cycle edges and generated actions remain in the bounded internal model observation, not final notices. A bounded or failed investigation is labeled incomplete, not exhaustive. Final diagnostic overhead has a small fixed allowance independent of the answer budget; excess notices are summarized rather than clipped mid-sentence, while cited source pointers are preserved. Recommendations in tool output are not authorization to execute them.

Upstream `TRUNC` markers reporting omitted, clipped, or hidden results produce one concise incompleteness warning (not a raw footer dump), even when other notices consume the report allowance; zero-count markers alone do not.

Search emits a physical-line count (`Content: N lines`, zero when content is omitted) before each raw content block. Only headers outside those blocks assign search provenance: header-shaped content cannot create a new source pointer. Unframed legacy search content may be retained as evidence, but cannot introduce additional trusted headers. Explain body previews, including warning-shaped text, remain source evidence rather than CLI notices or new `File:` provenance. Structure `T <test path> -> <source path>` hint rows attribute the hint to the test file, not the generic `Tests` heading.

Historical reports, documentation examples, and references to other projects do not establish implementation in the current repository. Ask must corroborate those implementation claims with indexed code, or explicitly report that the subsystem is unconfirmed here. Documentation may support a cited explanation of uncertainty. This is a model instruction, not a semantic entailment guarantee; real-provider checks are needed in addition to citation validation.

## Global model configuration and Pi backend

Template creation is shared by npm postinstall and setup/doctor. The source
installer explicitly invokes the same bootstrap and displays its path even when
npm hides lifecycle output. npm installs with scripts disabled require a later
`idx doctor`; `--foreground-scripts` exposes npm's postinstall message. Existing
symlink or nonregular targets are preserved and reported as warnings, not followed.
The template is written to a private temporary file before exclusive publication
at the final path. A failed write must not leave a partial `.env` that a later
invocation would mistake for an existing user configuration.

Ask lazily reads the current user's `~/.config/idx/.env`, or `$XDG_CONFIG_HOME/idx/.env` when `XDG_CONFIG_HOME` is absolute. npm installation and every `idx doctor`/setup path ensure a commented template exists there; existing regular files and symlinks are never overwritten. Creation is optional: failures produce a sanitized actionable warning and do not block installation or doctor. Newly created configuration directories are private (0700) and the file is exclusive-created with mode 0600. The installer reports the resolved path when created (doctor reports it whether newly created or already present). All setting examples remain commented and explicitly warn against storing real credentials in shared files. This location is independent of the working directory/project and shared by all idx instances for the user. Project-local dotenv files are never loaded. Process environment values override file values, including explicitly empty strings; missing files are normal. Loading does not mutate process environment or write the file. The consumed settings are `IDX_ASK_BACKEND`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `IDX_ASK_MODEL`, `IDX_PI_PROVIDER`, `IDX_PI_MODEL`, `PI_CODING_AGENT_DIR`, and the retry, fallback, and per-model limit settings documented below. The file must be a regular file at most 64 KiB, parsed with Node dotenv semantics, without expansion or shell execution. Read/parse/configuration errors are sanitized. Configuration does not affect embeddings. Document indexing also reuses the configured provider for optional, best-effort structured purpose classification; it does not run the ask tool loop.

The default backend is `openai`, with model `gpt-6-luna` using `OPENAI_API_KEY`; `IDX_ASK_MODEL` and `OPENAI_BASE_URL` may override model and API base. Ask sends the question, bounded retrieved excerpts, and the current in-memory conversation to the configured provider. OpenAI uses native Responses API function calls with strict tool schemas, `store:false`, reasoning `none`, a 20-second per-call timeout, a 256 KB request cap, a 100 KB response cap, and sanitized errors. HTTPS is required except for loopback HTTP; URL credentials/query/fragment and redirects are rejected. Tool output is returned through native function-call result messages. Native assistant state is retained within the invocation for reasoning/tool-call protocol continuity, never as a saved conversation.

`IDX_ASK_BACKEND` accepts only `openai` (default) or `pi`. Pi requires explicit `IDX_PI_PROVIDER` and `IDX_PI_MODEL`; it does not inherit the OpenAI model setting. It uses an existing installed `@earendil-works/pi-coding-agent` SDK with public `ModelRuntime` support (tested with 0.87.1), discoverable from idx's package resolution or the `pi` executable on PATH. Missing/incompatible installations fail safely. The runtime resolves its own stored authentication/model registry, optionally under `PI_CODING_AGENT_DIR`; idx does not parse/copy auth files. OAuth refresh may update Pi's own auth state. Backend failures never select an unconfigured alternative.

Each Pi model turn is a direct runtime completion, not an agent session. Only idx's allowlisted tool definitions and this invocation's messages participate. Pi's built-in tools, extensions, skills, prompt templates, project instructions, saved session history and session persistence are not loaded. Runtime initialization restores cached model catalogs with network model-catalog refresh disabled. Requests run in an isolated Node child using argv (no shell), with request data on stdin, a 20-second hard timeout, 256 KB request cap and 100 KB output cap. Tool calls and tool-result messages use Pi's native message protocol; idx executes and validates calls. Native assistant state, including provider signatures, is retained for subsequent turns. Raw child stderr/provider failures are not surfaced. Unsuccessful, malformed or incomplete completions produce the safe failure guide, never lexical fallback.

Search result regions, both code and documents, are untrusted evidence, not command metadata: a source or summary line beginning `Recommendation:`/`Verify:` must not be promoted into notices. Generated search `Read next` footers remain available to the model for necessary follow-up, along with architecture's complete numbered `Actions` section, but do not routinely appear in final notices. Split search blocks repeat the original source path/range so excerpts retain attribution. Retrieval guidance is not authorization to execute a suggested command.

## Execution boundary and limits

`IDX_ASK_RETRIES` is an integer from 0 to 5 (default 2), counting extra attempts per model turn for transient inference errors. Backoff and attempts consume the remaining overall deadline; each attempt remains bounded to at most 20 seconds. Retries do not replay completed retrieval tools. Deterministic configuration and malformed-response errors do not consume transient retries.

Optional fallback settings are `IDX_ASK_FALLBACK_BACKEND`, `IDX_ASK_FALLBACK_PROVIDER`, `IDX_ASK_FALLBACK_MODEL`, `IDX_ASK_FALLBACK_API_KEY`, and `IDX_ASK_FALLBACK_BASE_URL`. The fallback model is required to enable fallback. Its backend defaults to the primary backend; a Pi fallback may inherit the primary Pi provider when applicable. OpenAI-compatible fallback credentials/base URL default to the primary settings unless explicitly overridden. Partial invalid settings fail safely. All settings obey the same global dotenv/environment precedence and remain commented in the installation template.

After an unavailable primary exhausts applicable retries, a configured fallback is selected once and remains selected for the rest of this invocation. Retries and selection are disclosed outside generated prose, including when both fail. Native model state/signatures must not cross the model/backend boundary: the fallback receives a fresh conversation seeded with the original question and collected observations, marked as untrusted data; later fallback turns preserve only its own native state. There is no fallback tool execution outside the allowlist and no automatic search fallback.

The model supplies validated tool arguments, not flags or executable strings. Paths are project-relative and cannot traverse outside the project, including through existing symlinks. Audit requires a known task-changed file path and runs with `--no-semantic`; it never broadens a missing target to all project changes. Child processes use the current idx entry with an argv array and no shell. Removed wiki routes and model-authored mutation/check commands are rejected. Migration/skill-refresh preflights, automatic updates, and automatic indexing are skipped for ask and its retrieval children. Ask never changes source or writes an answer cache.

Each native tool schema exposes only that tool's applicable fields and modes (context: hybrid/lexical/semantic; search additionally supports symbol; deps: modules/calls). Required query/target arguments remain required; unused nullable fields may be omitted and are normalized to null. Unknown fields, incompatible non-null fields, unsupported modes/directions, and unsafe paths are rejected. Explain requires a symbol name or `path::symbol`; a bare file path is rejected before child execution with guidance to use AST or search. Validation errors returned to the model identify the invalid argument category so it can correct a call without weakening the read-only boundary. Retrieval execution errors are never reflected to the model verbatim, even if they resemble validation errors. For broad project orientation, README/docs search and context should be tried early; structure is not an invitation to page through the whole tree.

Bare `explain` file paths include backslash-separated paths and common root-file suffixes such as `.json` and `.yaml`. Dotted symbol names without a known file suffix remain valid; ambiguous names ending in a file suffix should use explicit `path::symbol`.

Questions are 1–4000 characters without control characters. The loop allows at most eight model turns (including final synthesis), twelve tool attempts and 120 seconds overall. A final synthesis turn, when possible, has no available tools. Invalid calls consume the same bounded attempt budget and may return tool errors for correction; they never execute. Every tool call in a batch receives a matching result before the next model turn. A retrieval child has a 30-second timeout and 256 KB capture limit; per-call timeouts are reduced to the remaining total deadline. Tool payloads and the accumulated transcript are bounded, with explicit truncation/incompleteness notices rather than silent data loss.

`--budget <tokens>` is an integer from 200 to 20000 (default 2000), requesting maximum model output tokens per turn. It is clamped to that model's output limit and available context. It is not a cap on total paid tokens across turns/retries or the entire rendered output: source pointers and bounded diagnostics are outside it. Provider tokenization and reasoning overhead may affect the usable answer length. Each invocation starts fresh; existing historical ask cache files are not used. Underlying tools retain their own pagination and retrieval limits; upstream TRUNC/NEXT hints are available in model observations for follow-up when needed.

Primary model limit overrides are `IDX_ASK_CONTEXT_TOKENS` and `IDX_ASK_MAX_OUTPUT_TOKENS`. Fallback overrides are `IDX_ASK_FALLBACK_CONTEXT_TOKENS` and `IDX_ASK_FALLBACK_MAX_OUTPUT_TOKENS`; they are independent and never inherit primary limits. Context overrides accept integers 2048–2000000; output overrides accept 1–200000. Pi uses the selected model's catalog context window and output limit; explicit overrides may lower but never raise known catalog limits. OpenAI-compatible endpoints do not uniformly expose context/output metadata, so unknown models use conservative configurable defaults of 16000 context and 2000 output tokens, not a claim about their real capabilities.

Each request accounts for instructions, tool schemas, the question, observations, native history, protocol headroom, and reserved output. Without a model tokenizer, input uses a conservative UTF-8 byte-based estimate, not exact token usage or billing. Overlarge histories are rebuilt as bounded, explicitly untrusted observations while preserving the original question and citation IDs in retained evidence, with a visible compaction/omission notice. Native tool state is either retained intact or discarded as a whole, never replayed with orphan results. Relevant unresolved diagnostics are represented in the bounded final report even if their model view is shortened. A base question/instruction/tool payload that cannot fit fails safely. On fallback, limits are recomputed for the newly selected model rather than reusing primary limits.
